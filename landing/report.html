Executive summary

A single unauthenticated request exposed this application's production database credentials — enough for full compromise.

Kryx identified 5 confirmed exposures on the public surface, including one critical issue. The application leaks its configuration and version-control metadata to anyone on the internet, with no authentication required. The headline risk is an exposed configuration file that discloses live database username and password, opening a direct path to full data exfiltration. Source code is also reconstructable from exposed .git and .svn metadata, giving an attacker a map to find further weaknesses.

None of these are theoretical: each was verified by Kryx fetching the resource and confirming the leak. Remediation is straightforward and is included per finding.

Detailed findings

CriticalExposed configuration — production database credentialsKRX-01
Location
GET https://brokencrystals.com/config.json — 200 OK · application/json
What we found

The application serves config.json publicly with no authentication. It contains live database connection details — username and password for the production environment, plus test and development credentials.

Proof
$ curl https://brokencrystals.com/config.json
{
  "production": {
    "username": "super_admin_lynx",
    "password": "1A2S3D4_F5G…",          (redacted in this sample)
    "database": "database_production",
    "host": "dbhost-production",
    "dialect": "mysql"
  }
}
✓ Tool-confirmed — file fetched and parsed by Kryx
Business impact

Anyone on the internet can authenticate to the production database and read, modify, or export all data. This is a full-confidentiality and full-integrity compromise.

Remediation

Remove config.json from the web root immediately; block static config files at the web server; and rotate every leaked credential now — assume it is already compromised.

HighExposed environment file (.env)KRX-02
Location
GET https://brokencrystals.com/.env — 200 OK (794 bytes)
What we found

The framework's .env file is publicly readable, exposing application configuration (database settings, mail, cache, and key material placeholders).

Proof
$ curl https://brokencrystals.com/.env
APP_NAME=Laravel
APP_ENV=local
APP_DEBUG=true
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=laravel
…
✓ Tool-confirmed — file fetched and parsed by Kryx
Business impact

Discloses internal configuration and any secrets stored in .env, aiding deeper compromise. APP_DEBUG=true in production further leaks stack traces and internals.

Remediation

Block dotfiles at the web server (nginx/apache), move secrets out of the web root, disable debug in production, and rotate any exposed secrets.

MediumExposed Git repository metadataKRX-03
Location
GET https://brokencrystals.com/.git/config — 200 OK
What we found

The .git directory is exposed. An attacker can download it and reconstruct the application's full source code and commit history.

✓ Tool-confirmed — resource fetched by Kryx
Business impact

Source disclosure hands attackers a map of the application — hard-coded secrets, hidden endpoints, and logic flaws — dramatically lowering the effort to find further vulnerabilities.

Remediation

Deny access to .git at the web server, and never deploy a working copy to production.

MediumExposed SVN working-copy databaseKRX-04
Location
GET https://brokencrystals.com/.svn/wc.db — 200 OK
What we found

The SVN .svn/wc.db metadata file is publicly readable, again allowing source reconstruction.

✓ Tool-confirmed — resource fetched by Kryx
Remediation

Block .svn directories at the web server; remove version-control metadata from deployed artifacts.
